# Avito Backend Trainee Assignment Autumn 2026
## CJM для клиента
### Поиск заведения
Пользователь открывает список заведений и фильтрует их по категории и рейтингу. 

Связь с сервером через `GET /restaurants`


Пользователь может столкнуться с проблемой, что в списке ресторан показывается, но на самом деле он закрыт (на текущий момент не принимает заказы). 
В таком случае необходимо добавить статус open/closed для ресторана.

### Просмотр меню заведения
Пользователь получает блюда и цены. 

Связь с сервером через `GET /restaurants/{id}/menu`, где `id` - это ID ресторана.


Пользователь также может получить состав блюда, обратившись напрямую к нему. 

Связь с сервером через `GET /restaurants/{id}/dish/{dish_id}`, где `dish_id` - это ID блюда.

Пользователь может столкнуться с проблемой, когда блюдо в меню есть, но на кухне оно закончилось.
В таком случае нужно добавить блюду свойство `in_stock`, которое принимает `true`/`false`

### Добавление блюда в заказ
Пользователь добавляет блюдо в заказ, выбирая его "модификаторы". 
Он может добавить доп. ингридиенты (например, доп. ломтик сыра к бургеру).


Связь с сервером через `POST /cart/items`. 


Пользователь может столкнуться с ситуацией, когда он попробует добавить блюда из разных ресторанов.
Добавим правило, что в заказе можно иметь блюда только из одного и того же ресторана.
Если он хочет добавить блюдо из другого ресторана, то сделаем разные корзины для ресторана A, ресторана B и т.д.

### Просмотр корзины
Пользователь может просмотреть свою корзину. 

Связь с сервером через `GET /cart`.


Может возникнуть проблема, пока пользователь собирал корзину, блюда в ресторане закончилось.
Для решения нужно проверять состояние наличия блюда в ресторане при каждом вызове `GET /cart`.

### Изменение корзины
Пользователь удаляет или меняет количество блюд в корзине. 

Связь с сервером через `DELETE /cart/items/{dish_id}` - удаление блюда из корзины (в случае, если количество установлено на 0 или блюдо удалили),
`PATCH /cart/items/{id}`.


Проблема может возникнуть, когда на клиенте количество установилось на < 0.
В таком случае нужно делать проверку на количество блюд перед обновлением в базе.
Если количество <= 0, то удалять товар.

### Оформление заказа
Пользователь оформляет заказ: вводит адрес, выбирает способ оплаты и оформляет заказ.

Связь с сервером через `POST /orders` с `"event_type": "created"`.


Может возникнуть проблема, когда пользователь указал адрес доставки, находящийся вообще в другом городе.
Для решения этой проблемы необходимо проверять зону доставки ресторана перед оформлением.


### Отмена заказа после оформления
Пользователь может отменить заказ после оформления (например, когда его уже начали готовить).


Связь с сервером через `POST /orders/{id}/cancel`.


Проблема может возникнуть, когда пользователь попытается отменить заказ, который уже доставлен.
В таком случае проверим, что статус заказа находится в new, accepted или in_process.

## CJM для заведения
### Просмотр меню
Заведение просматривает список всех блюд, цены и статус их наличия в ресторане.
Связь через `GET /admin/restaurants/{id}/menu`.


### Управление меню (добавление блюда)
Заведение добавляет новые блюда в свой каталог. Для блюда указывается название, описание, состав и цена.


Связь с сервером через `POST /admin/restaurants/{id}/dishes`. 


Может возникнуть проблема, когда заведение пытается добавить блюдо с пустым названием, отрицательной или пустой ценой.
Решить можно валидацией на стороне сервера.

### Управление меню (изменение блюда)
Заведение изменяет блюдо: название, описание, состав, наличие и/или цену.

Связь с сервером через `PATCH /admin/restaurants/{id}/dishes/{dish_id}`.


Может возникнуть проблема, когда ресторан изменяет блюдо, которое уже заказал пользователь.

В таком случае, когда пользователь создает заказ, то блюдо копирует в таблицу order_items,
копируя актуальные на момент заказа название, цену, количество и модификаторы, оставляя ссылку на блюдо в таблице блюд.

Когда пользователь захочет посмотреть состав уже сделанного заказа, то мы обратимся к таблице order_items, получим от туда dish_name и dish_price.
Они были сохранены на момент заказа и не поменяются, если заведение поменяет название или цену именно у блюда.



Еще может возникнуть проблема, когда заведение изменило наличие блюда на "нет в наличии", но блюдо уже заказано.
В таком случае блюдо не пропадает у пользователя из уже оформленного заказа.


### Управление меню (удаление блюда)
Ресторан удаляет блюдо из своего меню.

Связь с сервером через `DELETE /admin/restaurants/{id}/dishes/{dish_id}`.

Может возникнуть проблема, когда ресторан удаляет блюдо, которое заказал пользователь.
В таком случае нужно архивировать блюдо, скрывая только с видимости в списке, а не удалять его полностью.


### Обработка заказа
Заведение получает новый заказ через polling `GET /admin/orders`. 
Заказ можно как отклонить через `POST /admin/restaurants/{id}/orders/{order_id}/cancel`,
так и принять через `POST /admin/restaurants/{id}/orders/{order_id}/accept`.

Возможна проблема, когда ресторан игнорирует заказ.
Чтобы у пользователя не зависал заказ, можно добавить таймаут 10 минут на принятие/отклонение заказа.
Если время прошло, то заказ автоматически отменяется.

### Обновление статуса заказа
Заведение изменяет статус заказа. Оно может изменить его на `accepted` -> `in_process` -> `ready`.

Связь с сервером `PATCH /admin/restaurants/{id}/orders/{order_id}/status`.

Возможна проблема, когда пользователь отменил заказ, но ресторан продолжает его видеть как оформленный.
Для этого нужно проверять состояние заказа.



## Стек
- Язык программирования: C#, .NET9.0
- Фреймворк Web API: ASP.NET
- Архитектура: Clean Architecture, паттерн CQRS с использованием MediatR
- База данных: PostgreSQL
- ORM: EntityFramework Core
- Инфраструктура: Docker, Docker Compose
- Тестирование: xUnit + Moq
- Документация API: [Scalar](https://scalar.com/docs-for/dotnet)
