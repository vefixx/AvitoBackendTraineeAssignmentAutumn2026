# CJM (клиент)

## Описание пользователя

**Персона:** обычный пользователь Авито.Кухня (сервис доставки еды).
**Цель:** выбрать подходящее заведение, сформировать заказ из доступных блюд и оформить доставку по указанному адресу.
**Начальная точка:** пользователь открывает web-приложение.
**Конечная точка:** пользователь получает заказ либо заказ отменяется.

## Пользовательский путь клиента

### 1. Поиск заведения

**Цель:** найти подходящее заведение, в котором пользователь сможет заказать блюда.

**Действия пользователя:**

1. Открывает страницу со списком заведений.
2. Просматривает доступные заведения.
3. При необходимости выбирает фильтрацию: категорию кухни.
4. Просматривает результаты поиска.
5. Выбирает подходящее заведение.

**Ожидания:**

- Пользователь видит список доступных заведений.
- Может отфильтровать заведения по категории кухни.
- Может просматривать заведения постранично.
- Получает актуальную информацию о заведениях.

**Эмоции:** заинтересованность, желание найти подходящий вариант.

**Возможные проблемы:**

- Список заведений пуст.
- По выбранной категории нет заведений.
- Заведение временно закрыто.

**Результат:** пользователь выбрал заведение и переходит к просмотру его меню.

### 2. Выбор заведения

**Цель:** познакомиться с заведением и убедиться, что оно подходит для оформления заказа.

**Действия пользователя:**

1. Открывает страницу выбранного заведения.
2. Изучает название, описание и категорию кухни.
3. Проверяет, открыто ли заведение.
4. Переходит к просмотру меню.

**Ожидания:**

- Пользователь получает актуальную информацию о заведении
- Видит статус доступности заведения.
- Может перейти к меню выбранного заведения.

**Эмоции:** заинтересованность, ожидание.

**Возможные проблемы:**

- Заведение закрылось.
- Заведение больше не существует.
- Меню заведения недоступно.

**Результат:** пользователь переходит к изучению меню либо возвращается к поиску другого заведения.

### 3. Изучение меню

**Цель:** выбрать блюда, которые пользователь хочет заказать.

**Действия пользователя:**

1. Открывает меню выбранного заведения.
2. Просматривает доступные блюда.
3. Изучает названия и цены блюд.
4. Открывает подробную информацию об интересующем блюде.
5. Изучает описание и состав блюда.
6. Выбирает блюдо для добавления в корзину.

**Ожидания:**

- Пользователь видит только блюда, доступные для заказа.
- Может просматривать меню постранично.
- Может получить подробную информацию о конкретном блюде.
- Видит актуальную стоимость блюда и его состав.

**Эмоции:** заинтересованность, предвкушение выбора

**Возможные проблемы:**

- В меню отсутствуют доступные блюда.
- Выбранное блюдо больше недоступно.
- Информацию о блюде отсутствует или устарела.
- Заведение закрылось во время просмотра меню.

**Результат:** пользователь выбрал блюдо и готов добавить его в корзину.

### 4. Формирование корзины

**Цель:** сформировать заказ из выбранных блюд.

**Действия пользователя:**

1. Выбирает блюдо из меню.
2. Указывает необходимое количество.
3. Добавляет блюдо в корзину.
4. При необходимости повторяет действия для других блюд.
5. Может изменить количество ранее добавленного блюда.
6. Может удалить блюдо из корзины.
7. Просматривает текущее содержимое корзины.

**Ожидания:**

- Пользователь может добавлять несколько разных блюд.
- Может изменять количество каждого блюда.
- Может удалять ненужные блюда.
- Видит актуальное содержимое корзины.
- Видит актуальную стоимость позиций.
- В корзине находятся блюда только одного заведения.

**Эмоции:** удовлетворение от формирования заказа.

**Возможные проблемы:**

- Попытка добавить блюдо из другого заведения.
- Блюдо закончилось после открытия меню.
- Пользователь пытается указать количество больше допустимого.
- Пользователь пытается добавить некорректное количество блюда.
- Цена блюда изменилась после добавления в корзину.

**Результат:** пользователь сформировал корзину и готов перейти к оформлению заказа.

### 5. Проверка корзины

**Цель:** убедиться, что заказ содержит все необходимые блюда в правильном количестве.

**Действия пользователя:**

1. Открывает корзину.
2. Проверяет список добавленных блюд.
3. Проверяет количество каждого блюда.
4. Проверяет стоимость позиций.
5. При необходимости изменяет количество или удаляет блюда.
6. Принимает решение перейти к оформлению заказа.

**Ожидания:**

- Корзина содержит актуальную информацию о блюдах.
- Пользователь видит количество и стоимость каждой позиции.
- Пользователь может исправить состав заказа.
- Пользователь понимает итоговую стоимость заказа.

**Эмоции:** уверенность в правильности сформированного заказа.

**Возможные проблемы:**

- Одно из блюд больше недоступно.
- Корзина оказалась пустой.
- Информация о стоимости изменилась.

**Результат:** пользователь подтверждает готовность оформить заказ.

### 6. Оформление заказа

**Цель:** отправить сформированный заказ в выбранное заведение.

**Действия пользователя:**

1. Переходит к оформлению заказа.
2. Указывает адрес доставки.
3. Проверяет состав заказа.
4. Подтверждает оформление заказа.
5. Ожидание результат оформления.

**Ожидания:**

- Заказ успешно создается.
- Указанный адрес находится в зоне доставки заведения
- Все блюда доступны для заказа.
- Пользователь получается подтверждение создания заказа.
- Пользователь получается идентификатор созданного заказа.

**Эмоции:** предвкушение, ожидание успешного оформления.

**Возможные проблемы:**

- Адрес находится вне зоны доставки.
- Одно или несколько блюд закончились.
- Заведение закрылось.
- Корзина пуста.
- Данные заказа не прошли проверку.

**Результат:**

- При успешном оформлении пользователь получается подтверждение создания заказа.
- При ошибке пользователь получает информацию о причине и может исправить данные или изменить состав корзины.

### 7. Отслеживание заказа

**Цель:** узнать текущее состояние заказа и понимать, на каком этапе находится его выполнение.

**Действия пользователя:**

1. Открывает информацию о созданном заказе.
2. Просматривает текущий статус заказа.
3. Периодически обновляет информацию о заказе.
4. Следит за изменением статуса.
5. При необходимости принимает решение отменить заказ.

**Ожидания:**

- Пользователь может получить информацию о своём заказе.
- Видит актуальный статус.
- Понимает, принят ли заказ заведением.
- Может отслеживать переходы между статусами.

**Эмоции:** ожидание, заинтересованность, иногда беспокойство.

**Возможные проблемы:**

- Заведение долго не принимает заказ.
- Заказ автоматически отменён, если не был принят в течение 10 минут.
- Пользователь не может получить информацию о заказе.
- Заказ отклонён заведением.

**Результат:** пользователь получает актуальную информацию о состоянии заказа.

### 8. Отмена заказа

**Цель:** отменить ранее оформленный заказ, если пользователь больше не хочет его получать.

**Действия пользователя:**

1. Открывает информацию о заказе.
2. Проверяет текущий статус заказа.
3. Принимает решение отменить заказ.
4. Подтверждает отмену.
5. Получает результат операции.

**Ожидания:**

- Пользователь может отменить заказ, пока это разрешено бизнес-правилами.
- После отмены статус заказа изменяется на cancelled.
- Пользователь получает подтверждение отмены.

**Эмоции:** желание быстро решить возникшую ситуацию.

**Возможные проблемы:**

- Заказ уже находится в статусе `ready`.
- Заказ уже отменён.
- Заказ не существует.
- Заказ невозможно отменить из-за текущего статуса.

**Результат:**

- При успешной отмене пользователь получает подтверждение.
- Если отмена невозможна, пользователь получает объяснение причины.
